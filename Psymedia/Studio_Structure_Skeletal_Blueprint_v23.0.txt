======================================================================
3. ARCHITECTURAL PRINCIPLES
======================================================================

3.1 LEAN FIRST
Build the smallest reliable system capable of producing the episode.

3.2 SEPARATION OF CONCERNS
Keep production, communications, AI, archive, publishing and business
functions distinct.

3.3 ONE PERSISTENT AI DESK
There is one CC_AI_DESK for the entire Classies Chronicles franchise.
Episodes do not receive separate AI Desks.

3.4 EPISODE DATA REMAINS EPISODE-OWNED
The episode archive is authoritative for episode-specific information.
The AI Desk stores intelligence infrastructure and references, not the
episode's raw media or permanent episode-specific knowledge.

3.5 PROVIDER NEUTRALITY
Calling platforms and storage providers are replaceable endpoints.

3.6 HUMAN EDITORIAL AUTHORITY
AI may assist, converse and eventually operate autonomously within defined
boundaries, but editorial, consent, licensing and emergency controls remain
human-governed.

3.7 REBUILDABLE DERIVED DATA
Catalogs, indexes, hashes and retrieval caches are derived and rebuildable.

3.8 FAIL SAFE
Missing sources, invalid permissions, provider failures and stale indexes
must produce controlled failure rather than invented or unauthorized output.

1. microphone placement
2. microphone distance
3. clean source gain

19. PODCAST COMMUNICATIONS MODULE
======================================================================

The Pavilion is the Guest Communications Desk and uses Voicemeeter Potato
as the communications bus for Host ↔ Guest ↔ AI interaction.

The system is designed to prevent each participant from hearing their own
returned audio while allowing:

    HOST <-> GUEST
    HOST <-> AI
    GUEST <-> AI

The semantic communications buses are:

    A1 = Host Monitor
    B1 = Call Transmit
    B2 = AI Input
    B3 = Production Reserve

Conceptually:

    B1 = HOST + AI
    B2 = HOST + GUEST
    AI RETURN is excluded from B2
    GUEST RETURN is excluded from B1

AI return is separately controlled and may be routed to host and guest
without returning to AI input.

Calling applications remain replaceable endpoints, including WhatsApp,
Google Meet, Zoom, Riverside, Microsoft Teams and future providers.

application I/O, mix-minus matrix, troubleshooting, testing and operating

CC_AI_DESK is one persistent franchise-level AI control plane for all

- persistent persona

- prompt methodology
- provider/runtime configuration
- retrieval configuration
- source catalog

- automation

- operational logs

- raw video
- raw audio
- full episode media
- arbitrary member exports
- private/unapproved material
- episode-specific research as permanent global knowledge

    CURRENT_EPISODE
    CURRENT_SEASON
    ALL_APPROVED_EPISODES
    GLOBAL_CHRONICLES

    SQLite + FTS5

    EPISODE
       ↓
    TRANSCRIPT
       ↓
    POST-EPISODE ANALYSIS
       ↓
    PERSONA PROPOSAL
       ↓
    PRODUCER REVIEW
       ↓
    APPROVE / REJECT
       ↓
    VERSIONED PERSONA CHANGELOG

AI MUTE must remain independently controllable.

25. AI OPERATING MODES
======================================================================

    AI receives permitted conversation but does not speak.

    AI provides producer-facing assistance without automatically entering
    the live programme.

CO-HOST
    AI participates as a controlled spoken participant.

AUTONOMOUS
    AI may reasonably initiate, respond, challenge, question and contribute
    within defined production boundaries.

AUTONOMOUS is not the default commissioning mode.

Independent control:

    AI MUTE

AI MUTE must be capable of silencing AI audio even if:

- the model hangs
- the UI fails
- retrieval fails
- network latency increases
- an AI provider fails

49. VERSION 22.2 CHANGE LOG
======================================================================

Version 22.2 — 2026-08-16

This version refactors the previous integrated v22.1/v22.0 material into a
true skeletal Studio Blueprint.

Major changes:

1. Reduced the Podcast Communications Module to one concise architectural
   section and delegated all detailed implementation to its specialist file.

2. Reduced the AI Desk Architecture to one concise architectural section
   and delegated all detailed implementation to its specialist file.

3. Preserved the persistent one-Desk / many-episode architecture.

4. Preserved episode-owned source-of-truth architecture.

5. Preserved the canonical Pavilion → Blue Yeti → Daakro → ENVY physical
   programme/recovery path.

6. Corrected the earlier architectural ambiguity around virtual routing:
   Voicemeeter Potato is now formally recognized as the current Pavilion
   communications bus because remote guest + AI mix-minus is an actual
   production requirement. It does not replace the established physical
   programme-feed architecture.

7. Preserved the semantic communications contract:
       A1 = Host Monitor
       B1 = Call Transmit
       B2 = AI Input
       B3 = Production Reserve

8. Preserved OBS as the master programme recorder.

9. Preserved REAPER as the Pavilion stem/recovery recorder.

10. Preserved 44.1 kHz as the pilot commissioning standard.

11. Preserved 720p/30 as the conservative initial OBS target for the ENVY.

12. Preserved MKV master recording with remux to MP4.

13. Preserved independent AI MUTE as a production safety subsystem.

14. Preserved LISTEN → ASSIST → CO-HOST → AUTONOMOUS progression.

15. Preserved permission-aware retrieval and source traceability.

16. Added explicit source hashing and index-versioning principles from the
    detailed AI Desk architecture.

17. Added explicit safe-failure behaviour for stale indexes, missing sources,
    revoked consent, provider failure and UI failure.

18. Added the controlled Buzzjuice API/MU-plugin boundary without making it
    a prerequisite for initial local commissioning.

19. Added incremental Node.js + PowerShell automation progression.

20. Preserved future semantic retrieval as an evidence-driven enhancement,
    not a commissioning prerequisite.

21. Preserved pilot/commercial asset distinction and licensing review.

22. Preserved dual-recording, synchronization and acceptance-test gates.

23. Removed redundant low-level configuration details that belong in the
    specialist module documents.

24. Clarified that OBS tracks cannot separate a source that is already mixed.

25. Clarified that consumer AI voice interfaces are commissioning endpoints,
    not necessarily the permanent Studio AI Participant interface.

26. Maintained the lean-first philosophy while allowing proven production
    requirements to justify additional architecture.

50. MAINTENANCE POLICY
======================================================================

Update this Studio Blueprint when:

- workstation roles change
- hardware changes materially
- the Studio topology changes
- the communications architecture changes
- the AI Desk architecture changes materially
- consent/licensing architecture changes
- publishing architecture changes
- a pilot exposes a structural problem
- a new production requirement changes system boundaries

Do NOT duplicate low-level operational procedures from the specialist
documents into this file.

Update the specialist document instead when the change is specific to:

- Voicemeeter
- calling applications
- mix-minus routing
- AI Desk schemas
- catalog implementation
- retrieval internals
- persona governance implementation
- automation scripts
- producer UI internals
